# Lexara → Pantheon background capability audit

This is an execution audit, not a claim that every Pantheon engine has been live-proven for every category. The deterministic API test is `node scripts/test-lexara-background-chat-e2e.cjs`; it exercises the real router, investigation, conversation orchestrator, and HTTP/SSE surfaces with fixture discovery, crawlers, answer provider, and authentication. `node --import tsx scripts/test-pantheon-30-category-fixtures.cjs` exercises each of the 30 canonical categories separately through fixture-backed Lexara/API paths with OpenRouter and Firecrawl disabled. Neither fixture run is a live-source test. The live exercise below used real public network content and the existing Pantheon adapters, without storing personal data.

**Live exercise:** With both optional provider keys removed from the test process, “What does the National Archives Museum depict? https://www.archives.gov/museum” reached one-pass `evidence-sufficient`. The fetched official page's subject-matched description was emitted as evidence before the endpoint, then quoted in Lexara's `completed` response with its source URL. A prior live attempt exposed CSS ahead of the useful JSON-LD description; the evidence display now selects the subject-relevant passage instead of displaying page-header CSS. A separate focused retrieval invoked the six-primary-crawler route and a two-primary-crawler supplemental run. No personal records were retained. Search-index pages that produced challenge responses were rejected, not converted into negative search results.

**Regression checks:** deterministic chat API fixtures (including real Lexara→Pantheon routing with stubbed external services), all 30 category fixture paths, semantic routing and follow-ups, providerless answer fallback, capability execution, report evidence lifecycle and layout, retrieval behavior, and Neon failover contract passed. The API reports `jobCompleted: false` for partial, unavailable, failed, clarification, and consent-handoff Pantheon turns; an HTTP turn ending does not mean verified research completed. `verify:lexara-realization` now passes with the ordinary first crawler pass bounded to 6 seconds; an explicitly requested deep investigation may use 12 seconds on its first pass. Fixture coverage also checks named-subject natural-language routing, category selection, and permission-refusal handling. These checks do not replace a live-source exercise. Overflow was inspected directly: the expected table already exists, synthetic transactional insert/read passed and rolled back, and live Lexara storage create/read passed with the synthetic row removed. No live schema mutation was needed. Controlled-source fixtures cover authorized and still-blocked access, but no licensed restricted-source credential was configured for a live controlled-source check.
