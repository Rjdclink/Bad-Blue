GLOBAL OBJECTIVE

> Goal: End up with a Bad Blue app that is structurally clean, fully functional, SEO-optimized, AI-accurate, database-healthy, syntactically flawless, and correctly wired end-to-end — with no missed bugs, no missed syntax errors, and no unexamined feature or connection.



Everything is covered:

Officer search

AI-powered legal consultation → routes user input to petition / complaint / §1983 lawsuit

FOIA request drafting → routes to correct department email or falls back to contact.badblue@gmail.com

Petition drafting → name gathering → city council routing or fallback to contact.badblue@gmail.com

Complaint drafting → appropriate department routing or fallback to contact.badblue@gmail.com

Lawsuit drafting → including “Bad Blue option” routing to contact.badblue@gmail.com

Welcome emails on sign-in and confirmation emails with draft copies to user email

SEO, routing, AI provider usage, caching, error handling

Database migrations, tables, availability, and correctness

Syntax correctness, import/export correctness, and file-to-file connection correctness


The agent performs the work and reports findings.
The architect reviews every finding meticulously and tells the agent exactly what to fix.

PHASE A — INTENSIVE ANALYSIS & SYSTEM-WIDE INSPECTION

Agent inspects. After each section, it reports findings to the architect, and the architect double-checks and recommends corrections.


---

A.0 – Exhaustive Syntax Error Hunt (Every Single Line)

Agent:

Goes through every single line of code in the entire app, extremely meticulously:

All TypeScript/JavaScript files in /server, /client, /providers, /hooks, /components, /lib, etc.

Any config files that contain executable or parsed code (where syntax matters).

Looks for:

Missing commas, semicolons where required by the code style/tooling.

Unbalanced parentheses, brackets, braces.

Misplaced or unmatched quotes and template strings.

Invalid function signatures.

Wrongly ordered async / await / export / default keywords.

Typo’d keywords (retun, funtion, etc.).

Any line that would cause a parser, TS compiler, or bundler to fail.



For every syntax issue found:

Immediately logs it as a specific finding (file, line, problem description).

Reports it directly to the architect in detail.



Architect:

For each reported syntax issue:

Meticulously reviews the exact line and surrounding context.

Confirms whether the agent’s diagnosis is correct.

If the diagnosis is correct, provides an exact, explicit fix for that line (and any nearby lines if needed).

If the agent misread something, corrects the agent’s understanding so the agent doesn’t misclassify similar lines later.



The agent then applies the architect’s fix and, if needed, re-checks that file.
