# Subscription Phase 3: Signup & Plans API Endpoints

## Overview
Completed backend foundation for user signup and subscription plan retrieval, preparing for Square subscription integration.

## Files Created

### 1. `server/routes/auth.routes.ts`
Authentication routes for user signup, status, and logout.

**Endpoints:**

#### POST /api/auth/signup
Create a new user account with `pending_payment` status.

**Request Body:**
```json
{
  "email": "user@example.com",
  "password": "securepassword123",
  "first_name": "John",
  "last_name": "Doe"
}
```

**Response (200):**
```json
{
  "success": true,
  "userId": "uuid-here",
  "user": {
    "id": "uuid-here",
    "email": "user@example.com",
    "first_name": "John",
    "last_name": "Doe",
    "status": "pending_payment"
  }
}
```

**Validation:**
- All fields required
- Email format validation
- Password minimum 8 characters
- Email uniqueness check
- Returns 400 for validation errors, 409 for duplicate email

**Security:**
- Password hashed with bcrypt (10 rounds)
- Email normalized to lowercase
- Session cookie set automatically (httpOnly)

---

#### GET /api/auth/user/status
Get current user's status and subscription information (requires authentication).

**Response (200):**
```json
{
  "user": {
    "id": "uuid-here",
    "email": "user@example.com",
    "first_name": "John",
    "last_name": "Doe",
    "status": "active",
    "square_customer_id": "sq_customer_xxx"
  },
  "subscription": {
    "id": 1,
    "status": "active",
    "square_subscription_id": "sq_sub_xxx",
    "start_date": "2025-01-01",
    "renewal_date": "2025-02-01",
    "plan_name": "LegalWhat Subscription",
    "price": 2599,
    "currency": "USD",
    "interval": "monthly"
  }
}
```

**Note:** If user has no subscription, `subscription` field will be `null`.

---

#### GET /api/auth/logout
Logout current user and destroy session.

**Response (200):**
```json
{
  "success": true
}
```

### 2. `server/routes/plans.routes.ts`
Subscription plans retrieval endpoints.

**Endpoints:**

#### GET /api/plans
Get all active subscription plans.

**Response (200):**
```json
{
  "plans": [
    {
      "id": 1,
      "name": "LegalWhat Subscription",
      "price": 2599,
      "priceFormatted": "$25.99",
      "currency": "USD",
      "interval": "monthly",
      "squarePlanId": "PLACEHOLDER_SQUARE_PLAN_ID"
    }
  ]
}
```

**Use Case:** Display available plans on landing page or signup flow.

---

#### GET /api/plans/:id
Get a specific plan by ID.

**Response (200):**
```json
{
  "plan": {
    "id": 1,
    "name": "LegalWhat Subscription",
    "price": 2599,
    "priceFormatted": "$25.99",
    "currency": "USD",
    "interval": "monthly",
    "squarePlanId": "PLACEHOLDER_SQUARE_PLAN_ID"
  }
}
```

**Returns 404** if plan not found or inactive.

## Integration with Existing System

### Authentication Compatibility
- Uses Phase 2 middleware (`ensureAuthenticated`) for protected routes
- Compatible with existing Passport authentication in `server/auth.ts`
- Session management via `req.session.userId`

### Database Integration
- Uses Phase 2 database helper (`server/lib/db.ts`)
- Queries Phase 1 schema (users, plans, subscriptions tables)
- Parameterized queries prevent SQL injection

### Session Handling
- Leverages existing session middleware from `server/auth.ts`
- Session cookie automatically set on signup
- httpOnly flag ensures client-side JavaScript cannot access session

## Security Features

### Password Security
- bcrypt hashing with 10 rounds (industry standard)
- Passwords never stored in plain text
- Salt automatically generated by bcrypt

### Input Validation
- Email format validation (regex)
- Password length requirement (8+ characters)
- All fields required check
- Duplicate email prevention

### Session Security
- Secure cookie in production (HTTPS)
- httpOnly prevents XSS attacks
- SameSite policy prevents CSRF

### Error Handling
- Generic error messages for security (don't leak DB details)
- Specific validation errors for user experience
- All errors logged server-side for debugging

## Next Steps (Phase 4)

### Square Subscription Integration
1. **Create Square Customer**
   - POST /api/subscriptions/create-customer
   - Store `square_customer_id` in users table

2. **Create Square Subscription**
   - POST /api/subscriptions/subscribe
   - Use Square Subscriptions API
   - Store subscription details in subscriptions table

3. **Handle Square Webhooks**
   - POST /api/webhooks/square
   - Verify webhook signature
   - Update subscription status based on events
   - Log to transactions table

4. **Update User Status**
   - Active subscription → users.status = 'active'
   - Payment failed → users.status = 'past_due'
   - Canceled → users.status = 'canceled'

### Frontend Integration
1. **Landing Page**
   - Display plans from GET /api/plans
   - "Get Started" button → signup form

2. **Signup Form**
   - POST to /api/auth/signup
   - Redirect to Square hosted checkout

3. **Subscription Payment (Square Hosted Checkout)**
   - Backend creates checkout session via Square API
   - User redirects to Square's secure hosted payment page (`https://square.link/...`)
   - Payment processed on Square's infrastructure (PCI compliant)
   - After payment, Square redirects back to application
   - Webhook updates subscription status in database
   
   **Benefits of Hosted Checkout:**
   - Full PCI compliance without certification burden
   - Square handles all payment security and fraud detection
   - Professional payment UX with mobile optimization
   - Reduced codebase complexity
   - No sensitive payment data touches application servers

4. **Protected Routes**
   - Add `ensureActiveSubscription` middleware to `/welcome` and `/legal-tools`
   - Redirect to subscription page if not active
